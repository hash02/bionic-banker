# Competitive Proof Surface Benchmark

## Purpose

This benchmark guides Bionic Banker toward a sharp AI-agent founder portfolio for finance systems: product-forward, evidence-backed, and understandable to AI+finance-literate readers without becoming a generic compliance brochure.

## Audience lens

Bionic Banker is for recruiters, collaborators, executives, investors, builders, and serious learners who want to understand what Hash is building across AI agents, finance, wallet risk, AML evidence, fraud triage, and human-gated automation.

## Positioning conclusion

Bionic Banker should not copy one category. The right blend is:

- **Unit21 / Sardine / Alloy:** agentic fraud + AML operations language.
- **Chainalysis / TRM / Elliptic:** wallet/risk intelligence, case-building, traceable evidence, compliance lifecycle.
- **LangGraph / LangSmith / Claude Code / OpenAI Agents:** traces, guardrails, handoffs, human-in-the-loop, reviewable artifacts.
- **Vercel / Linear / Stripe / Supabase / Retool / PostHog / GitHub Next:** compressed claim, artifact-forward proof, readable routes, visible product system.
- **Founder portfolio sites:** clear builder identity and public proof of taste/judgment.

Best hero line:

> AI agents for finance risk — evidence-first, human-reviewed.

Best support line:

> Bionic Banker turns wallet signals, AML checks, fraud alerts, and agent workflows into review-ready evidence packets with visible sources, traces, guardrails, and human decision boundaries.

## Benchmarked patterns

### AI-agent infrastructure and workflow products

#### LangChain / LangSmith — https://www.langchain.com/

- **Thesis:** powering the agent development lifecycle.
- **Reader path:** build, test, monitor, deploy, observe, evaluate.
- **Proof strategy:** traces, evals, observability, customer logos, production lifecycle.
- **Boundary language:** understand what your agent is doing; human review and automated evals.
- **Bionic Banker should copy:** lifecycle framing and “show what the agent did” proof.
- **Avoid:** generic agent-platform language without finance-specific artifacts.

#### LangGraph — https://www.langchain.com/langgraph

- **Thesis:** balance agent control with agency.
- **Reader path:** orchestration, human-in-the-loop, memory, streaming, reliability.
- **Proof strategy:** reliability via concrete control mechanisms.
- **Boundary language:** prevent agents from veering off course; human checks steer and approve actions.
- **Bionic Banker should copy:** control-with-agency language for finance workflows.
- **Avoid:** framework jargon above the fold.

#### CrewAI — https://crewai.com/

- **Thesis:** accelerate AI-agent adoption and deliver production value.
- **Reader path:** builders/leaders, orchestrate/build/observe/manage.
- **Proof strategy:** adoption metrics, role split, agent management platform.
- **Boundary language:** guardrails, workflow tracing, RBAC, human-in-the-loop agent training.
- **Bionic Banker should copy:** builder + leader split and capability blocks.
- **Avoid:** broad enterprise claims without evidence.

#### Claude Code — https://claude.com/product/claude-code

- **Thesis:** built for developers, working where developers already work.
- **Reader path:** install command, task examples, surfaces, enterprise/security.
- **Proof strategy:** concrete operating surfaces and reviewable actions.
- **Boundary language:** user reviews, runs CI, and decides what ships.
- **Bionic Banker should copy:** exact task prompts such as “Investigate this wallet” and “Generate an escalation memo.”
- **Avoid:** implying agents replace accountable reviewers.

#### OpenAI Agents / Codex — https://developers.openai.com/

- **Thesis:** developer platform and use-case library for agent workflows.
- **Reader path:** use cases, SDK, traces, guardrails, handoffs, examples.
- **Proof strategy:** concrete workflow examples and primitives.
- **Boundary language:** guardrails, handoffs, tracing, human-in-the-loop.
- **Bionic Banker should copy:** primitive model: agents, tools, evidence stores, guardrails, handoffs, human review.
- **Avoid:** turning homepage into docs before the value is clear.

#### Devin / Cognition — https://devin.ai/

- **Thesis:** AI software engineer with case-study proof.
- **Reader path:** problem, decision, solution, results, quotes, metrics.
- **Proof strategy:** hard case-study numbers and human project approval.
- **Boundary language:** human kept in the loop to manage and approve changes.
- **Bionic Banker should copy:** case-study structure, but only with defensible prototype metrics.
- **Avoid:** ROI/customer claims that are not proven.

### RegTech / AML / risk intelligence companies

#### Chainalysis — https://www.chainalysis.com/

- **Thesis:** blockchain intelligence for investigations, risk, and security.
- **Reader path:** screen wallet/transaction, alert, trace, investigate, recover/escalate.
- **Proof strategy:** deterministic methodology, ground-truth evidence, court/agency credibility.
- **Boundary language:** risk appetite, thresholds, alerts, regulatory obligations.
- **Bionic Banker should copy:** evidence you can inspect; traceable wallet risk; methodology notes.
- **Avoid:** court-tested/regulator-approved/recovery claims.

#### TRM Labs — https://www.trmlabs.com/

- **Thesis:** agents and intelligence to fight crime; operating layer for public safety.
- **Reader path:** intelligence, software/agents, disruption network.
- **Proof strategy:** case-building, tracing, analyst notes, alert history, ownership.
- **Boundary language:** show work, evidentiary cases, case workflows.
- **Bionic Banker should copy:** from signal to evidence packet; every alert includes trigger/context/rationale/review note.
- **Avoid:** law-enforcement/national-security overreach.

#### Elliptic — https://www.elliptic.co/

- **Thesis:** blockchain analytics for financial crime risk management and compliance.
- **Reader path:** due diligence, screening, monitoring, investigation, alerting.
- **Proof strategy:** compliance lifecycle and configurable risk rules.
- **Boundary language:** escalations, monitoring, risk rules.
- **Bionic Banker should copy:** screen → monitor → triage → investigate → evidence.
- **Avoid:** generic compliance-platform claims.

#### Sardine — https://www.sardine.ai/

- **Thesis:** agentic financial-crime platform for fraud prevention and AML.
- **Reader path:** fraud, AML, transaction monitoring, device/behavior signals, KYC/KYB, investigations.
- **Proof strategy:** modular journey blocks and AI agents for alert review.
- **Boundary language:** agents help AML teams move faster from review to resolution.
- **Bionic Banker should copy:** AI agents assist with alert review, evidence gathering, and case narrative drafting.
- **Avoid:** “stop fraud” or “prevent attacks” unless the system actually blocks transactions.

#### Unit21 — https://www.unit21.ai/

- **Thesis:** agentic AI platform for fraud and AML operations.
- **Reader path:** detection, investigation, decisioning, feedback loop.
- **Proof strategy:** show-your-work agents, audit trails, documented risk reasoning.
- **Boundary language:** every AI decision fully traceable; mapped to policies; backed by evidence.
- **Bionic Banker should copy:** AI-assisted L1 triage, show-your-work risk reasoning, human decision boundary.
- **Avoid:** unqualified “regulator-ready” claims.

#### Alloy — https://www.alloy.com/

- **Thesis:** identity and fraud prevention platform for financial services.
- **Reader path:** onboarding, transaction activity, ongoing monitoring, risk profile updates, case review.
- **Proof strategy:** orchestration and actionable AI.
- **Boundary language:** fully auditable agentic automation.
- **Bionic Banker should copy:** actionable AI for wallet/transaction risk and evolving risk profiles.
- **Avoid:** complete-view claims without explicit data sources.

#### ComplyAdvantage — https://complyadvantage.com/

- **Access note:** direct pages were blocked, but public LLM resources surfaced themes.
- **Thesis:** AML data and financial-crime risk intelligence.
- **Reader path:** sanctions/watchlists, adverse media, customer screening, ongoing monitoring, fraud, agentic workflows.
- **Proof strategy:** education-heavy AML content and risk intelligence.
- **Boundary language:** human-led AI / AI-augmented compliance teams.
- **Bionic Banker should copy:** human-led AI for AML evidence review.
- **Avoid:** vague “better AML data” without showing provenance.

## Recommended Bionic Banker message architecture

### Hero

**AI agents for finance risk — evidence-first, human-reviewed.**

Bionic Banker turns wallet signals, AML checks, fraud alerts, and agent workflows into review-ready evidence packets with visible sources, traces, guardrails, and human decision boundaries.

### Proof strip

- Wallet Risk: reviewer-ready score and rationale.
- AML Evidence: provenance, checks, and explicit authority limits.
- Fraud Triage: synthetic alert to evidence packet and reviewer note.
- Agent Workflow: move, review, gate, artifact.
- Site Health: proof QA checks and self-audit status.

### Product primitive model

- Signal intake
- Risk scoring / rule hit
- Evidence packet
- Agent trace / action log
- Human review gate
- Bounded artifact

### Boundary line

Bionic Banker does not make final compliance decisions, execute trades, control wallets, file reports, or guarantee fraud/AML outcomes. It demonstrates how AI agents can prepare inspectable evidence for human review.

## What Bionic Banker should copy

- **From Unit21:** show-your-work AI, audit trails, L1 triage, human decision boundary.
- **From Chainalysis/TRM:** wallet intelligence, case-building, traceability, evidence packets.
- **From Elliptic:** compliance lifecycle: screen → monitor → triage → investigate.
- **From LangGraph/LangSmith:** control with agency, traces, evals, human-in-the-loop.
- **From Claude Code/OpenAI Agents:** task examples, guardrails, handoffs, reviewable artifacts.
- **From Linear/Vercel/Supabase:** compressed claim and clean route structure.
- **From GitHub Next/founder sites:** maturity labels and builder identity.

## What Bionic Banker should avoid

- Regulator-approved.
- Court-tested.
- Stops fraud.
- Prevents money laundering.
- Guaranteed AML correctness.
- Production-grade sanctions screening.
- Detects criminals.
- Replaces analysts.
- Bank-grade.
- Enterprise/customer/ROI claims without proof.
