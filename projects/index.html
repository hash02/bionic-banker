Project features

Each project is shown as a working surface.

The page focuses on what a project does: the feature, the input, the output, the evidence link, and the decision it deliberately leaves to people.

Visible proof

Projects show the artifact first.

Each card explains what the project does, what goes in, what comes out, and where to open the demo, article, source, or evidence surface.

Useful features

Features are described as working capabilities.

Review queues, evidence packets, source trails, control maps, scoring rules, dashboards, and checklists are shown as project features, not process notes.

Clear limits

Boundaries protect the reader and the work.

Finance, AI, wallet, payment, and compliance projects state what they do not decide or execute so the value is understandable without overclaiming.

How to read this page
