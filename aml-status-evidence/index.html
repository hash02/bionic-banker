AML Status Evidence

The status is only useful when the supporting evidence, control boundary, and review record are visible.

This page makes the AML Layer 1 status evidence visible without turning it into a compliance claim. It shows the contract, the artifact provenance, the planner boundary, and the parts that still stay local.

Evidence contract

A status row has to earn trust.

Gate behavior

The planner can pause. It cannot execute.

Every compliance gate keeps may_execute set to false. Clean means proposal-only, not action authority.

Artifact provenance

The evidence record shape is defined before the public claim.

The local contract defines JSON and Markdown evidence artifacts, latest aliases, and SHA-256 sidecars so a later reader can inspect what backed the status.

70-ops-logs/aml-evidence/<timestamp>-aml-evidence.{json,md} plus aml-evidence-latest aliases and .sha256 sidecar
What is visible

Public-safe claims

  • AML status can only be treated as evidence-backed when stub is false, counts exist, source metadata exists, rules are loaded, and freshness checks pass.
  • Planning/advisor gate outputs carry proposal_clean and may_execute fields, with may_execute remaining false on every branch.
  • Canonical local evidence artifacts are defined as JSON, Markdown, latest aliases, and SHA-256 sidecars under the vault operations log pattern.
  • Mission Control UI surfaces evidence status, blockers, source freshness, evidence artifact status, artifact path, evidence hash, and artifact age.
  • The public page is a evidence surface, not an operational compliance product.
What stays bounded

Not an execution system

  • may_execute: false
  • KYC approval authority: false
  • Wallet or trade authority: false
  • Filing authority: false
  • Deploy authority: false
